# October 11–12 host64k campaign: all measured arms

**Selected production: C4 = DS41F 1.0.0.** All arms use the same EXL3 checkpoint, TP3, K5 maximum, native FP8 KV allocation and qualified 64K-page host baseline. This is separate from the October 9 X11c campaign. C4 means a candidate name here; concurrency C4 means four requests elsewhere.

There were 19 planned arms including B0. Eighteen were measured once through the full campaign sequence; N9 resolved to a no-op after 361 baseline decode steps showed the observed sizes already covered. Each Owen decode point has three measured repeats after its discarded warmup. There are no model-level confidence intervals for the single Hermes pass.

The primary Hermes suite, the [Christopher Owen benchmark adapted from spark-ds41f](OWEN-BENCHMARK.md), and the supplemental request-overlap curve are reported separately. All throughput numbers are tokens per second, but their denominators differ. Detailed machine-readable exports are in [results/20261012-host64k-campaign](../results/20261012-host64k-campaign/); [summary CSV](../results/20261012-host64k-campaign/summary.csv) and [full-precision summary JSON](../results/20261012-host64k-campaign/summary.json) are convenient for analysis.

## What each variant actually changes

| Arm | Relative to B0 / combination | Rationale and observed limitation |
|---|---|---|
| B0 | Fresh X11c on kernel 7.0 / 64K pages | Same-host reference, not the old October 9 score copied forward |
| N1 | Full valid K5 verification for eligible single-request pure decode | Avoid over-short verification; isolated C1 declined, so full verification is not a universal win |
| N2 | Stock lagged mHC for 1–6 pure-decode rows; fused mixed/prefill retained | Reduce small-batch overhead; phase metadata and eager tiny-prefill fallback are required |
| N3 | Reusable logits scratch and batched position keys | Cheaper same-distribution draft bookkeeping; isolated C3 improved, C1/C8 declined |
| N4 | Four-warp specialization of the existing large-row EXL3 kernel | Exact TP3 routed shapes, MUL1 K3/K4, FP32 accumulation retained; decode K path unchanged |
| N5 | Exact compatible indexer optimization | Selection/masking must remain correct; good isolated C1/C3 did not imply the best combined C3 |
| N6 | Bounded decoder replay, cache/metadata/vision/SP integration | Largest isolated long-prefill gain; lower Hermes C8, full 128K phase completed |
| N7a | Pure-prefill row-partition threshold 512 instead of 2048 | More work distributed sooner, more communication opportunities; no isolated prefill improvement |
| N7b | Same threshold 256 | Even earlier partitioning; not a monotonic improvement over 512 or baseline |
| N8a | B12X MXFP8 A16 small rows 1–6, split-K 2 | Different small dense projection work split; larger rows unchanged, mixed results |
| N8b | Same eligible rows with split-K 1 | Avoid reduction/split overhead; near-baseline C8, weaker C1/C3 |
| N9 | Trace-selected additions, at most three graph buckets | No eligible uncovered benefit in the observed trace; no separate measurement |
| C1 | N1 + N2 | Single-stream specialization; C1 did not beat B0 |
| C2 | N1 + N2 + N3 | Add draft overhead reduction; gains do not simply add |
| C3 | N1 + N2 + N3 + N4 | Strongest Hermes C1 in this campaign, without the replay prefill gain |
| **C4 / 1.0.0** | **N1 + N2 + N3 + N4 + N6** | **Selected long-context compromise: large prefill gain and completed 128K phase; not highest Hermes C8** |
| C5-indexer | C3 + N5 | Highest Hermes C8 in this campaign; lower C3 and no replay prefill gain |
| C5-sp512 | C3 + N7a | Alternative row partitioning; inspect complete suite rather than one cell |
| C5-sp256 | C3 + N7b | Strong C3, reasonable C8; temporary end-of-test deployment, later replaced by selected C4 |

N5 optimizes the indexer already inherited from X11c; it does not mean the earlier I1/I2 indexer is absent from C4. Similarly, N8 is an additional small-row tactic experiment, not the original introduction of B12X. Exact source maps and environment/compiler settings are available in [the experiment archive](EXPERIMENT-REPLAY.md).

## Completeness, correctness and interpretation

All 18 arms passed the recorded bounded text/vision cold/hot quality checks and completed the Owen suite and supplemental curve. These checks protect the tested contracts; they are not a general model-quality benchmark.

Only **N6 and C4** completed the full 128K-C3 phase, including its hot part. The other arms retained incomplete results, commonly `ValueError: SSE closed without [DONE]` under the bounded phase. A starred 128K cold value is a successfully measured cold-prime component of an incomplete phase, not a completed 128K cold/hot test. Missing values are not zero. The original envelopes retain phase-level completeness and errors even where a higher-level suite flag is true.

The table does not support adding individual percentage gains to predict a combination. C4's Hermes C8 is lower than B0; C5-indexer's C8 is higher; N6 alone has higher 64K prefill than C4. The choice of C4 reflects long agent prompts and useful concurrency alongside its measured limitations. The campaign did not achieve both primary targets, Hermes C1 70+ and C8 180+.

## Audit and regenerate the tables

```bash
python3 results/20261012-host64k-campaign/summarize_results.py
python3 -m unittest discover -s tests
```

The numerical envelopes preserve original measurement precision and per-request counts. Private request bodies, generated answers/reasoning, machine addresses and operational identifiers are excluded. `source_file_sha256` and the original result digest identify retained private originals; they are not hashes of the redacted public JSON. This explicit distinction prevents a false checksum claim.

Earlier numerical campaigns remain under `results/` and [HISTORY.md](HISTORY.md). The archived original-source and corpus hashes establish provenance, not permission to publish private conversations. The public authored workloads and clearly labelled legacy surrogates are described in [BENCHMARKS.md](BENCHMARKS.md).
