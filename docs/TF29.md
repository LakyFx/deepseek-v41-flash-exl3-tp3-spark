# TF29: Mia EXL3 2.9 bpw, native TensorFold, TP3

TF29 uses the pinned Mia EXL3 export throughout its rank weights and the same native TP3 port, cache fixes and BF16 vision extraction as TF351. It has a smaller checkpoint and higher measured synthetic decode in several cells; that does not guarantee shorter completed agent tasks or better quality.

- [Source, attribution, exact pins and technical explanation](TENSORFOLD-TP3.md).
- [Complete installation](TENSORFOLD-INSTALL.md).
- [Results and quality scope](TENSORFOLD-RESULTS.md).
- [Qualified profile: TF29 / 3.3M](../tensorfold/profiles/TF29.json).

The published qualified profile is **3,300,000 logical pool tokens**, 401,408 request context, TP3, C8, MAX, 16 round rows and head snapshot budget 1 GiB. Use the 3,301,376-row RoPE kit and TF29 rank weights/model metadata on all nodes. TF29 has not been tested with the 10M pool; extra free memory is not a capacity qualification.

The three rank files total 215,248,585,443 bytes, approximately 71.75 decimal GB each, plus local Engram, vision and kernel assets. TF351 and TF29 together need approximately 473 GB just for those six rank files, excluding source checkpoints and additional assets.

```sh
python3 tensorfold/launch.py --config tensorfold/cluster.local.json --variant TF29 --rank 0
python3 tensorfold/launch.py --config tensorfold/cluster.local.json --variant TF29 --rank 1
python3 tensorfold/launch.py --config tensorfold/cluster.local.json --variant TF29 --rank 2
```

Those commands print only. Switch all three ranks as a group, keep their profiles and RoPE kit consistent, and begin with an empty runtime cache. Neither EXL3 weights nor KV snapshots are imported from the other engine by these scripts. Preserve independent C4 and TF351 installations for rollback.
