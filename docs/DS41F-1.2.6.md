# DS41F 1.2.6 — the production 5c recipe

**1.2.6 is the release name for the tested and now running 5c payload.** Renaming
and persistent startup installation did not rebuild/reload the model or change
the measured inference settings. The exact 1,139-file source tree is published
as `v126`, with hash-bound head/follower build receipts.

## What changed since 1.2.5 / K2a

**Preserve useful prefixes when pressure fragments available KV space.** A bounded
CPU planner can choose an eligible, previously restored idle donor, move its
state and update placement after native acknowledgement. It excludes protected
and live donors, requires useful saved positions, and retains an eviction
fallback. Planner work stays bounded (2 ms, 512 snapshots, 2,048 evaluations).
There is no background defragmentation or continuous GPU maintenance pass.

**Bound the additional copying.** Each new idle relocation and the total available
credit are capped at 320 MiB per rank, replenished at 8 MiB/s. A large useful
prefix can therefore fit a single move without allowing unlimited repeated
copies. The old copy-on-resume behavior is separate and unchanged. The configured
7M pool and 3 GiB snapshot cache are not enlarged. A full live 320 MiB copy stress
was not part of this release campaign; the cap is a bound, not a latency promise.

**Use the native cancellation contract.** Closing an owned TensorFold request
does not invoke a vLLM-specific abort endpoint. Durable image jobs still wait for
native termination receipts when dispatch outcome is uncertain; they never
silently replay accepted work. Reasoning effort/headroom is raised for standalone
image analysis. Agent conversations with images/tools/history retain their own
request budgets and existing routing rules.

**Collect bounded evidence when a rare image guard fires.** Repetition matching
preserves numeric table values. An opt-in observer can record a trigger tail and
the continuation from that same generation, privately. The exact historical
repetition trigger was discarded; all nine new image jobs passed, so this release
does **not** claim a definitive fix for every old rare rejection.

The observer is disabled without a private directory and an exact, expiring job-ID
allowlist. It records no prompts, images, authentication headers or raw SSE.
Its bounded text may contain private reasoning: never publish runtime files.
Under `ProtectSystem=strict`, an external diagnostics directory also needs a
narrow `ReadWritePaths=` entry. A private subdirectory of systemd `StateDirectory`
already uses the service's writable state mount. Verify service UID and actual
mount-namespace writability; directory ownership alone is insufficient.

## Build, install and launch

Follow the unchanged [1017 weights](DS41F-1.2.0.md), [host requirements](HOST-ENVIRONMENT.md)
and [TP3 installation](TENSORFOLD-INSTALL.md). Use the pinned Zig **0.17.0** toolchain
and new build/output directories. Never mix native recipes across the three ranks.

```sh
python3 tensorfold/extract.py --out /srv/ds41f-build-1.2.6
python3 tensorfold/variants/build.py build --recipe v126 \
  --build-root /srv/ds41f-build-1.2.6 --out /srv/ds41f-built-1.2.6 --zig zig
python3 tensorfold/variants/build.py install --built /srv/ds41f-built-1.2.6 \
  --runtime /srv/ds41f-runtime --variant 1.2.6
```

On the head only, after weight/model preparation:

```sh
python3 tensorfold/prepare_template.py --runtime /srv/ds41f-runtime --variant 1.2.6
```

The head's direct-output template is unchanged. Followers retain the original
1017 template. This creates a new metadata overlay and preserves original weights.
Set your topology in `tensorfold/cluster.local.json`, then print each local rank:

```sh
python3 -m tensorfold.launch --config tensorfold/cluster.local.json --variant 1.2.6 --rank 0
python3 -m tensorfold.launch --config tensorfold/cluster.local.json --variant 1.2.6 --rank 1
python3 -m tensorfold.launch --config tensorfold/cluster.local.json --variant 1.2.6 --rank 2
```

`--run` validates the exact native build receipt, binary identity, role-specific
template, model revision, rank/Engram files and RoPE capacity. The launcher applies
the pressure-planner flag and 320 MiB cap on every rank. It retains all existing
adaptive, RDMA, graph, Engram and cache settings. Preparation starts no services.

For public automatic startup use `TF_PROFILE=1.2.6` with the provided
`tensorfold/tp3@.service` and operator-owned topology/environment. Preserve network
readiness and the 1,800-second native peer startup window; enable the correct
local rank on each host. Put the gateway behind native readiness. Original
production additionally pins immutable assets/argv/module hashes, validates local
storage/Engram/RoPE/AOT, waits for peers/GPU readiness and checks native vision
control before admitting API traffic. Those private paths/topology are not
portable and are deliberately excluded from this repository.
