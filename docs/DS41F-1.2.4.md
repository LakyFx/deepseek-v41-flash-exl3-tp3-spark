completed-work time in the matched C1–C12 campaign. Same DeepSeek 1017 EXL3 weights

## 1. Prepare weights, topology and a fresh build directory

Use Linux, Python 3.10+ and the pinned Zig **0.17.0** toolchain. Follow
[1017 model preparation](DS41F-1.2.0.md) for the exact Hugging Face revision,
rank-cache/Engram ownership and template checks. Reuse those verified artifacts;
do not re-quantize or substitute an older Pollard checkpoint.

Follow [host/ABI requirements](HOST-ENVIRONMENT.md). From this repository:

```sh
python3 tensorfold/extract.py --out /srv/ds41f-build-1.2.4
```

The extractor validates the frozen source/kernel archive digests before creating
a new destination. Use a **fresh extraction for each recipe**, including a repeat
build; applying a recipe to already modified source is rejected.

## 2. Apply the exact measured source and compile

```sh
python3 tensorfold/variants/build.py build \
  --recipe cdef --build-root /srv/ds41f-build-1.2.4 \
  --out /srv/ds41f-built-1.2.4 --zig zig
```

This validates the pristine full source map, applies hash-addressed source
objects, checks the final full tree, runs CPU checks, and cross-compiles the
aarch64 head and follower executable. Its `BUILD.json` records source identity,
both executable hashes and CPU check log hashes. It does not load a model or
make inference requests. A new host build is not automatically GPU-qualified.

For a source-only inspection, add `--prepare-only`. That does not produce an
installable binary receipt; extract again before the actual build.

For another recipe, use the `--recipe` name in [the chooser](RECIPES.md).
In particular, uppercase `C` means the cumulative A+B+C experiment, whereas
`--recipe cdef` is the combined 1.2.4 release.

## 3. Install separately on all three ranks

Copy the complete built directory, this recipe checkout and prepared kit/model
artifacts to each operator-chosen rank. On each rank, use its actual runtime root:

```sh
python3 tensorfold/variants/build.py install \
  --built /srv/ds41f-built-1.2.4 \
  --runtime /srv/ds41f-runtime --variant 1.2.4
```

The installer checks the selected source manifest and binary hashes, then creates
a **new** `bin-1.2.4/` with both binaries and their receipt. It refuses an existing
destination. Keep previous binaries and profiles for rollback. All three ranks
must have the same source recipe and matching locally verified binary receipts.

Populate `tensorfold/cluster.local.json` from the example with your real rank
roots, master address, four RDMA devices, interfaces, peer masks and library path.
Use the existing model/kit readiness procedure, including RoPE tables of at least
`pool + 49` rows. There are no embedded production addresses or credentials.

## 4. Print, qualify and then serve

Print each command first:

```sh
python3 -m tensorfold.launch --config tensorfold/cluster.local.json --variant 1.2.4 --rank 0
python3 -m tensorfold.launch --config tensorfold/cluster.local.json --variant 1.2.4 --rank 1
python3 -m tensorfold.launch --config tensorfold/cluster.local.json --variant 1.2.4 --rank 2
```

`--run` verifies the exact recipe/build receipt, executable hashes, model revision,
template, rank artifacts and pool tables before replacing the **local launcher
process** with the rank executable. Coordinate rank starts in your maintenance
window using the [existing TP3 procedure](TENSORFOLD-INSTALL.md). It does not
manage other services or automatically overwrite boot configuration.

For a closed benchmark backend add `--benchmark`; rank 0 binds loopback and
enables benchmark controls. [Matched workflow procedure](../benchmarks/workflow/README.md).
Perform local startup and functional qualification before exposing an API.
Select 1.2.4 in your own service definition after that qualification if you want
it to survive a reboot; these preparation commands do not alter system services.

## How the learning layer fits together

The controller starts from fixed timing priors and updates cost/acceptance from
real verification rounds. It selects row allocation to improve expected useful
tokens per time, within R48. A prices the actual deepest verification shape;
D bounds host-time exploration; E renews stale cost banks on a valid observation.
B and C remove/overlap host work, and F changes admission ordering.

Only speculative **work allocation** changes. The target verifier, position-keyed
sampling contract and weight values remain the same. The state is local to the
process, not trained weights or a persisted learned model. The short benchmark
does not prove that every mechanism activated or that longer uptime always helps.
[Detailed learner design](ADAPTIVE-SPECULATION.md) · [mechanism boundaries and attribution](RECIPES.md).
