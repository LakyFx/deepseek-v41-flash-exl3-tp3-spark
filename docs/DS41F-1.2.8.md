# 1.2.8 — TP3 high-prefill recipe (AF-4K)

**1.2.8 is AF-4K, preserving the exact measured native source and runtime policy.**
It adds distributed prefill work, tuned EXL3 prompt kernels, 4K compute chunks,
Engram read-ahead fixes and bounded prompt scratch to 1.2.7. The smart KV and
speculation controllers remain. [Measurements and methodology](PREFILL-1.2.8.md).

| Setting | 1.2.8 |
| --- | --- |
| Model / weights | Same pinned 1017 EXL3 hybrid as 1.2.7; no re-quantization |
| Hardware | Three DGX Spark / GB10, TP3, switchless RoCE |
| Context | 401,408 tokens; prompt scratch 403,456 positions |
| Pool / checkpoint budget | 7,000,000 physical KV positions / 3 GiB head checkpoint cache |
| Serving / speculation | C12; adaptive K1–K5 under shared R48 ceiling; existing online learner |
| Prefill | 4,096 compute tokens; 2,048 physical KV quantum |
| Retention / copy | X4 smart controller, bounded 320 MiB/rank relocation and existing refill policy |
| Vision / reasoning | MAX serving default; standalone vision MAX/8K thinking + 32K final, two jobs |
| Network | Existing TP3 rank masks and automatic network-peer channels; no forced 2/8-channel experiment |

## Prepare the build and unchanged weights

Use the existing [1017 download and preparation](DS41F-1.2.0.md),
[host requirements](HOST-ENVIRONMENT.md) and [TP3 runtime layout](TENSORFOLD-INSTALL.md).
Use **Zig 0.17.0**, Linux ARM64 target, the published SM121 kernels and matching
NCCL/RDMA setup. Do not replace the 1017 weights with the older Pollard checkpoint.
Extract into a new directory; all older archives remain intact.

```sh
git fetch origin --tags
git checkout v1.2.8
python3 tensorfold/extract.py --out /srv/ds41f-build-1.2.8
python3 tensorfold/variants/build.py build --recipe v128 \
  --build-root /srv/ds41f-build-1.2.8 --out /srv/ds41f-built-1.2.8 --zig zig
```

The builder verifies the entire pinned source and base kernel kit, applies the
AF source objects, runs CPU checks, builds both native executables and stages
the matching AOT/auxiliary kernels under the output directory. Its BUILD.json
binds binaries, source tree and the exact prefill asset manifest. No inference,
SSH or service changes are performed by this command.

## Install on every rank

Prepare `/srv/ds41f-runtime` using the existing layout: `kit/` with token map,
base kernels and correctly sized RoPE tables; pinned model metadata/vision;
local rank cache and owned Engram files. Copy the complete verified build output
and recipe checkout to every rank, then run locally:

```sh
python3 tensorfold/variants/build.py install --built /srv/ds41f-built-1.2.8 \
  --runtime /srv/ds41f-runtime --variant 1.2.8
```

This creates `bin-1.2.8/` and isolated `prefill-1.2.8/` assets. The shared base
kit and older installed versions are preserved. The new AOT manifest includes
the original entries plus the masked TP3 attention variants; do not run AF with
the old manifest or omit `experts_ragged.cubin`. No live services are changed.

On the **head only**, create the exact direct-output model metadata overlay:

```sh
python3 tensorfold/prepare_template.py --runtime /srv/ds41f-runtime --variant 1.2.8
```

Followers keep the original 1017 template. Each follower must receive
`--prompt-context 401408`; the launcher supplies it automatically. Otherwise
the startup workspace contract will disagree or legacy large allocation will
be selected. Do not hand-edit the per-rank workspace or GPU math to bypass it.

## Launch and qualify your cluster

Fill the untracked `tensorfold/cluster.local.json` with your topology and the
installed runtime root on every node. Print and inspect all three commands:

```sh
python3 -m tensorfold.launch --config tensorfold/cluster.local.json --variant 1.2.8 --rank 0
python3 -m tensorfold.launch --config tensorfold/cluster.local.json --variant 1.2.8 --rank 1
python3 -m tensorfold.launch --config tensorfold/cluster.local.json --variant 1.2.8 --rank 2
```

During your maintenance window, close external ingress, stop the old native
generation together, and start followers and head on their respective hosts
with `--run`. Startup checks verify build receipts, kernels, weights, RoPE,
templates and all-rank prompt limits. Before exposing ingress, check native
health, text, repeated/growing prefix reuse, cancellation and images; confirm
`prefill_workspace_setup` reports 7M pool / 403456 prompt positions / chunk4096
on every rank. Preserve the 1,800-second peer startup window.

For the existing public systemd templates, select `TF_PROFILE=1.2.8` in your
operator-owned environment file and enable the activity-limited NVMe companion
for each local rank. Follow [1.2.7 startup/recovery guidance](DS41F-1.2.7.md#nvme-companion-and-startup):
the simple templates do not themselves implement coordinated multi-host recovery.
Use the [unchanged public gateway](GATEWAY.md) with your own credentials and URLs.
