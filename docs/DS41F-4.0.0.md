# 4.0.0 — four DGX Sparks, switchless TensorFold

**4.0.0 is the public release name for the deployed TP4 P3 recipe.** It keeps
the selected P2 compute path, exact native executables, weights and final CUDA
kernel set. The production settings are C16 / R48 / 9M KV / 3.5 GiB checkpoints.
This numbering separates the TP4 line from **[TP3 1.2.8](DS41F-1.2.8.md)**.
Both remain available in the same repository; no old release is replaced.

| Setting | TP4 4.0.0 |
| --- | --- |
| Model | DeepSeek V4.1 Flash **1017**, same pinned mixed-precision weights |
| Routed experts | EXL3 **~3.5101 bpw**; no re-quantization for TP4 |
| Hardware / transport | Four GB10 DGX Sparks, switchless cycle, RoCE v2 |
| Layout | Native-shape 2×2 distribution; four native rank caches |
| Context / prompt workspace | **401,408 / 403,456** positions |
| Shared physical KV pool | **9,000,000** positions, distributed across ranks |
| Head checkpoint budget | **3.5 GiB**, separate from the KV pool |
| Serving / speculation | **C16**, adaptive K1–K5 under **shared R48** verification ceiling |
| Prefill / physical allocation | **8,192** compute rows / **2,048** KV quantum |
| Controllers | Existing adaptive speculation learner and X4 smart KV retention |
| Relocation | Existing bounded **320 MiB per rank**, 8 MiB/s replenishment |
| Engram | Two exact owned partitions; partition `rank % 2` resides on each rank |
| Vision | MAX / 8K thinking + 32K final; two concurrent standalone image jobs |
| Gateway | C16; **8M reserved-token admission**, distinct from native 9M KV |

R48 is a maximum shared row budget, not 48 draft tokens for every request.
The learner adapts acceptance/cost estimates during the process lifetime.
The prefix controller uses verified return history and recomputation costs;
it does not know the user's task type or predict every future return.

## 1. Prepare the host and switchless transport

Use the [GB10 host requirements](HOST-ENVIRONMENT.md): Linux ARM64, compatible
NVIDIA driver, CUDA 13 / SM121, RDMA/verbs, and the same software versions on
all four nodes. This recipe does not upgrade drivers or reconfigure hosts.
Keep ordinary management Ethernet available throughout.

Connect a **cycle** with two physical neighbor links per node:

```text
rank 0 ───────── rank 1
  │                │
  │                │
rank 3 ───────── rank 2
```

Each physical link exposes two PCI-domain RDMA devices. Record the actual
device/interface names with `ibdev2netdev`, `rdma link`, `ip -br addr` and the
host's GID table. In the supplied topology, `neighbor_first` is the two-device
rail used by the first native exchange, and `neighbor_second` is its other
neighbor. Their **order must match the physical cycle**, including the opposite
port order on the neighbor; do not infer names from a different Spark's PCI IDs.
The source's `neighbor_gid` transport determines peers from the local rail.
Qualify every physical edge in both directions with RDMA bandwidth/latency and
byte-integrity checks before loading the model. Link-up alone is insufficient.

The NCCL library needs the credited cumulative dual-PCI-domain patch plus the
CTS acquire fence. `NCCL_ALGO=Ring` alone still leaves unwanted diagonal startup
connections on unpatched NCCL. Build a **separate library**, preserving TP3:

```sh
git clone https://github.com/LakyFx/deepseek-v41-flash-exl3-tp3-tp4-spark.git
cd deepseek-v41-flash-exl3-tp3-tp4-spark
git checkout v4.0.0
git clone https://github.com/NVIDIA/nccl.git /srv/nccl-tp4-base
git -C /srv/nccl-tp4-base checkout 73cf112295c33aee2b895f329f592f2a9b4b0f97
python3 -m tensorfold.tp4.build_nccl_ring \
  --base /srv/nccl-tp4-base --output /srv/ds41f-nccl-tp4
```

The builder verifies the pinned clean checkout, applies both patches, runs
CPU routing-handle checks and builds `libnccl.so.2.30.7` for SM121. Distribute
the complete verified output, including `BUILD.json`, to all four nodes.
Its `lib/` is the TP4 library path. Do not install it over a system/TP3 library.
No GPU qualification is implied by compilation. [Credits and patch details](../tensorfold/tp4/nccl-ring/README.md).

## 2. Stage the exact executables and kernels

Use a new build/runtime directory. The default path stages the exact measured
Linux ARM64 executables, with their complete source available in `v400`.

```sh
python3 tensorfold/extract.py --out /srv/ds41f-build-4.0.0
python3 -m tensorfold.tp4.build \
  --kit /srv/ds41f-build-4.0.0/kit --out /srv/ds41f-built-4.0.0
```

This verifies every reused and supplied kernel, stages `native/`, `prefill/`
and `BUILD.json`, and checks the exact binary hashes. The final AOT set has
**591 launch entries**, including decode/short-tail fixes. It includes the
P2 prompt MMA auxiliary module. Do not use the TP3 AF manifest or an earlier
TP4 prefill-only manifest.

For an optional source rebuild, add
`--source-build /srv/ds41f-build-4.0.0 --zig zig` to the second command, using
Zig **0.17.0**. It reconstructs and checks the full source, runs CPU checks
and builds both executables. Use a fresh extraction/output for each attempt.
Your build hashes may differ; destination serving qualification is required.
Full extraction/build is intended for Linux; upstream fixture filenames include
characters that cannot be materialized on NTFS.

## 3. Prepare exact TP4 weights, without changing quantization

The linked Hugging Face release contains **TP3** files. It is the verified
source for the byte-exact repartition below, **not a direct TP4 download**.
Use revision `8621801c1fc74aece1fa83e67c6ade3fde1e7894`:

```sh
hf download LakyFx/DeepSeek-V4.1-Flash-1017-EXL3-3.5bpw-TensorFold \
  --revision 8621801c1fc74aece1fa83e67c6ade3fde1e7894 \
  --local-dir /srv/ds41f-1017-source \
  --include 'models/TF351-1017/*' 'rank-cache/TF351-1017/*' \
    'engram-tp3/*' 'RELEASE-MANIFEST.json' 'verification/*'
```

Apply the [1017 release-manifest verification and sparse extraction](DS41F-1.2.0.md#download-one-rank-per-spark)
to **all three source ranks** before proceeding. Keep all producer and full
verification receipts. Retain sparse files; a sparse Engram wrapper's apparent
size is much larger than its allocated disk blocks. Preparation needs the
three input caches and four output caches, in addition to model/Engram assets;
use a suitably sized preparation disk. Nothing reads the running model's cache.

Prepare a fresh v400 source tree (Linux), without recompiling if using prebuilts:

If the optional source build already materialized `v400`, skip the first
command below and reuse that verified source for repartitioning.

```sh
python3 tensorfold/variants/build.py build --recipe v400 \
  --build-root /srv/ds41f-build-4.0.0 \
  --out /srv/unused-v400-prepare-only --prepare-only
python3 -m tensorfold.tp4.cache_repartition \
  --sources /srv/ds41f-1017-source/rank-cache/TF351-1017 \
  --recipe tensorfold/tp4/plan --source-code /srv/ds41f-build-4.0.0/source \
  --output /srv/ds41f-1017-tp4-ranks
```

The first repartition invocation is a dry run. Add `--write --vectorized-bytes`
(NumPy required for the optional fast byte-copy path) to create the four caches
in a **new output directory**. It verifies complete input SHA-256 values,
reconstructs native planner rectangles, drops only TP3 virtual zero-padding,
and independently rereads every output tensor and complete artifact. The
143,530 keys per rank are pinned. No dequantization or weight arithmetic occurs.

For Engram, put the three verified extracted directories at
`/srv/ds41f-engram-source/engram-r0`, `engram-r1`, `engram-r2` (symlinks to the
three source directories are fine). Each must contain `SOURCE.json` and its
two sparse safetensor files. Then:

```sh
python3 -m tensorfold.tp4.engram_repartition \
  --inputs /srv/ds41f-engram-source --kit /srv/ds41f-build-4.0.0/kit \
  --output /srv/ds41f-1017-tp4-engram
python3 -m tensorfold.tp4.prepare_model \
  --source /srv/ds41f-1017-source/models/TF351-1017 \
  --release-manifest /srv/ds41f-1017-source/RELEASE-MANIFEST.json \
  --out /srv/ds41f-1017-tp4-model
```

Engram ownership follows the first/last **12 hash columns**, not a naive
halfway split in the flattened table. Input owned-range hashes and output
readback are verified. The native metadata restores **64 heads / 8 o-groups /
129,280 vocabulary** and preserves the original provenance. The same exact
direct-output template is used on all four ranks. The BF16 vision shard and
tokenizer bytes remain unchanged.

## 4. Assemble each new runtime

Generate/reuse the [verified 10M RoPE tables](TENSORFOLD-INSTALL.md#5-generate-the-matching-rope-kit).
They cover 10,002,432 positions and support the configured 9M pool:

```sh
python3 tensorfold/make_rope.py --reference /srv/ds41f-build-4.0.0/reference \
  --kit /srv/ds41f-build-4.0.0/kit --pool 10000000
```

Copy the following into a **new**, independent runtime root on each node:

```text
/srv/ds41f-tp4-4.0.0/
  BUILD.json                 # from the TP4 builder
  native/                    # both exact executables
  prefill/                   # complete verified TP4 AOT + auxiliary modules
  kit/                       # base kit, token map, Engram metadata, 10M RoPE
  model/                     # prepared native TP4 metadata/tokenizer/vision
  rank-cache/
    rankNof4.bin             # only this node's rank cache
    rankNof4-HASH.bin        # regular hardlink, required for native discovery
    rankNof4.receipt.json
  engram-tp2-rP/             # P = N % 2; SOURCE.json and sparse tables
```

Keep sparse semantics and hardlinks during copying (for example, `rsync -aHS`). Copy only
rank N's cache; copy partition 0 to ranks 0/2 and partition 1 to ranks 1/3.
Retain the build receipt and NCCL receipt with their original bytes.
Recheck full cache hashes after transferring to another disk/host; startup
uses validated receipts/sizes rather than rereading tens of GB every time.

## 5. Configure, print, launch and expose ingress

Copy `tensorfold/tp4/cluster.example.json` to the ignored `cluster.local.json`
in the same directory. Fill **all four** rank roots, actual management address,
NCCL interface, fabric CIDR, four HCA names, two ordered neighbor rails, GID
index and the separately built NCCL library path. The example cannot run.

```sh
for rank in 0 1 2 3; do
  python3 -m tensorfold.tp4.launch \
    --config tensorfold/tp4/cluster.local.json --rank "$rank"
done
```

Close external ingress during the coordinated switch. Start all four ranks
on their respective hosts by adding `--run`. They retain the **1,800-second**
peer-start window. Do not run TP4 with `tensorfold.launch`, which deliberately
remains TP3-only. The TP4 launcher clears incompatible inherited TP3 knobs and
checks source/build identity, complete kernels, model geometry/template, rank
receipt, Engram ownership, RoPE lengths and the pinned patched NCCL library.

Before opening ingress, verify native health/text, tools, a growing reused
prefix, cancellation followed by another answer, all four rank identities,
and images. Observe memory/swap on **every** rank. Recorded P3 qualification
is linked below; a different operator's build/topology needs its own check.

For NVMe keepalive, use the unchanged activity-limited helper via:

```sh
python3 -m tensorfold.tp4.keepalive --config tensorfold/tp4/cluster.local.json \
  --rank 0 --unit YOUR_LOCAL_TP4_RANK_UNIT
```

Use the corresponding rank on every node. It reads only owned Engram ranges,
one aligned 4K probe at 25 ms while recent native disk-read activity is present;
it stops probing when idle. Preserve the original binary identity check.

Use the [existing gateway package](GATEWAY.md), your own credentials and
persistent state, plus the overrides in
[`gateway.env.example`](../tensorfold/tp4/gateway.env.example). Route both
text and vision to rank 0. Native 9M KV and gateway 8M admission are separate
limits. Set `DS41F_GATEWAY_PROFILE` to the absolute path of
[`gateway-profile.json`](../tensorfold/tp4/gateway-profile.json) in the installed
checkout. The portable entrypoint loads capacity from that JSON; plain
`LAGUNA_GATEWAY_MAX_CONCURRENCY` environment overrides alone are insufficient.
Never overwrite a private environment with an example file.

For systemd retain `LimitMEMLOCK=infinity`, `LimitNOFILE=1048576`,
`KillMode=control-group` and `MemorySwapMax=0` for model units. Start the same
immutable generation on all nodes; make gateway readiness depend on the whole
four-rank generation. A rank failure requires a **coordinated generation
restart after the missing peer returns**, not just restarting the head or
reusing old GPU KV. Operator-specific boot/recovery orchestration and SSH
credentials are intentionally outside the portable recipe. The launcher
does not install units or mutate a live cluster.

## Evidence, credit and rollback

[P3 workflow, memory, C16/image checks and P2 cold prefill](BENCHMARK-4.0.0.md)
are different measurement scopes. P3 completed **78/78** frozen workflow tasks,
with **327 requests**, **145,668 output tokens** and **908.31 seconds** of wave
time. No new benchmark was run merely to publish the 4.0.0 label. The retained
P2 cold-prefill median reaches **4,289 tok/s at 64K**, with zero cache hits;
that test used C12/7M/3 GiB rather than the final C16/9M/3.5 GiB settings.

Credit DeepSeek, Ashley Hart / TensorFold and the inherited EXL3/Triton work.
The switchless dual-domain transport patch is from **FujitsuPolycom/sparkring**;
the CTS fence is **Stanislav Bardyuk's** backport of NVIDIA/nccl#2393, obtained
through knapcio's recipe. [Source references](SOURCES.md#400-tp4-production).
Our tuning preserves these upstream credits and licenses.

Keep previous binaries, profiles, assets, network configuration and private
state. TP3 1.2.8 remains an independent three-node choice with its original
topology. Switching TP3/TP4 is a coordinated operator action, not a hot reload.
No historical recipes, benchmarks, tags or releases were removed.
